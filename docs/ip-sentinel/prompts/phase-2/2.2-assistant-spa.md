# 2.2 — Assistant SPA (streaming, tool trace)

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

## Context
2.1 already built the backend end to end: `AssistantController` exposes a synchronous
`POST /api/v1/assistant/chat` and a streaming `POST /api/v1/assistant/chat/stream` (SSE, via
`SseEmitter`, 120s timeout) that emits `tool_call` → `tool_result` events as the agent works, then one
terminal `answer` event carrying `{answer, citations[], aiAvailable, insufficient}`. `AiAssistantPage.tsx`
already exists, but only as a placeholder wired to the *synchronous* `/chat` endpoint: it posts one
prompt, shows a static "Analysing telemetry..." string while waiting, and renders the answer text with
no citations, no trace, and a client-only Basic/Pro upsell gate. It even imports `ShieldAlert` and
`AlertCircle` from `lucide-react` that are never used — placeholders for exactly the degraded-answer
states (`aiAvailable:false`, `insufficient:true`) this chunk needs to render. This chunk replaces that
placeholder body with a real streaming client against `/chat/stream`.

## Scope
**In:** an SSE client for `/chat/stream`, live tool/query trace rendering, final answer + citations,
degraded-state UI (`aiAvailable:false` / `insufficient:true`), in-session conversation history,
copy affordances, responsive layout, and closing the one real gating gap the streaming endpoint opens up.
**Out:** 2.4's full gating *policy* (customer data-only scope, disclaimers) — this chunk keeps the
existing Basic/Pro upsell card and Sidebar badge as-is. Teams ChatOps (2.3). Any backend change:
`AssistantController`/`AssistantAgentService` already emit everything this chunk needs.

## Dependencies
- 2.1 (`AssistantController.java`, `AssistantAgentService.java`, `AssistantAnswer.java`,
  `AssistantProgressListener.java`) — the streaming contract this chunk consumes.
- 0.8 SPA shell — `apiClient.ts` (bearer token + `X-Tenant-Id` header pattern), `AuthContext.tsx`
  (`entitlementTier`), the existing `/assistant` route and gated Sidebar nav entry.

## Deliverables

### 1. Streaming client (hand-rolled SSE, not `EventSource`)
- The browser's native `EventSource` only issues **GET** requests and cannot set custom headers, but
  `/chat/stream` is a **POST** that needs the same `Authorization: Bearer` + `X-Tenant-Id` headers
  `apiClient.ts` already attaches to `/chat`. Implement the client with `fetch()` +
  `response.body.getReader()`, buffering and splitting on blank lines to parse `event:`/`data:` frames.
- Before treating the response as an event stream, check `response.ok` / content-type: a role or
  entitlement failure (see Deliverable 4) returns a normal JSON error body on the initial response, not
  an SSE frame — read it the same way `apiClient.apiRequest` does, don't feed it to the SSE parser.
- Route each parsed frame to state updates: `tool_call` / `tool_result` append to the in-progress turn's
  live trace; `answer` finalizes that turn with the answer text, citations, `aiAvailable`, `insufficient`.
- If nothing terminal arrives before the SSE connection closes (server-side 120s cap, or a network drop),
  finalize the turn with a timeout/error state instead of leaving the trace spinning forever.

### 2. Tool trace, answer, and degraded states
- While a turn is in flight, render each `tool_call`/`tool_result` pair inline under it, in arrival order
  (tool name + query/args + result summary) — replacing the current static loading string, not just
  bolting the trace on beside it.
- On the terminal `answer`, replace the live trace with the final formatted answer and a citations list
  (one row per `{tool, query, summary}`).
- Wire the already-imported `ShieldAlert` (⇒ `aiAvailable:false`, degraded/AI-off styling) and
  `AlertCircle` (⇒ `insufficient:true`, "not enough evidence" styling) into visually distinct states —
  both still show the server-provided message text verbatim, just styled differently from a normal answer.

### 3. History, copy affordances, responsive
- Keep the existing in-session `messages` transcript model (user turn → trace → final answer, newest at
  bottom) — this is UI-only, per-tab state. The backend has no conversation persistence and each
  `/chat`+`/chat/stream` call is single-turn/stateless (`AssistantAgentService.answer` starts a fresh
  conversation every call); do not invent a history API or send prior turns back as context.
- Copy-to-clipboard on an answer's text and on an individual citation's query.
- Chat column and trace/citation rows reflow to full width on mobile, matching the 0.8 shell's
  responsive breakpoints; no horizontal scroll.

### 4. Gating / upsell (reuse, don't rebuild — close one real gap)
- Keep the existing `entitlementTier !== 'PRO'` upsell card and the Sidebar's gated `PRO` badge exactly
  as they are today.
- New: `chatStream` is `@RequiresEntitlement(PRO)` at the controller level, enforced by
  `EntitlementAspect` *before* the `SseEmitter` is created — a stale client-side `entitlementTier` (e.g.
  a downgrade that hasn't refreshed yet) can still hit start-of-stream with a plain
  `403 {status, error:"Forbidden", message}` body (`GlobalExceptionHandler`). Catch that on the initial
  `fetch()` response and show the same upsell state, not a raw "[Analysis Error]" bubble.

## Constraints / gotchas
- No `EventSource` — POST + custom auth headers rule it out; see Deliverable 1.
- Chat is stateless per call server-side; nothing here should try to multi-turn the backend.
- `aiops-web` has no frontend test framework configured yet (no vitest/RTL in `package.json`) — don't
  add one speculatively for this chunk; verify manually like the sibling SPA chunks (e.g. 1.4) do.
- Brand palette / Island Pacific styling only — match the existing inline-style conventions already used
  in `AiAssistantPage.tsx` rather than introducing a new styling approach.

## Implementation notes
- `apiClient.streamAssistantChat(prompt, onEvent)` (new export in `apiClient.ts`) is the hand-rolled SSE
  client: `fetch()` + `response.body.getReader()`, buffering on `\n\n` frame boundaries and parsing
  `event:`/`data:` lines per frame. Confirmed against the real wire format Spring's `SseEmitter` produces
  (`SseEventBuilder.data(Object)` JSON-serializes a `Map` with no embedded newlines for this payload
  shape, so each frame is one `event:`/`data:` line pair) rather than assumed.
- Non-event-stream responses (checked via `response.ok` and a `content-type` guard before any frame
  parsing) are read as plain JSON, reusing the same error-message extraction as `apiRequest` — this is
  what lets a 403 from `EntitlementAspect` on `/chat/stream` (thrown before the `SseEmitter` exists) fall
  through to the upsell state instead of a raw fetch error.
- `AiAssistantPage.tsx`'s `ChatMessage`/ `AssistantMessage` state model keys each turn by
  `crypto.randomUUID()` and merges `tool_call`/`tool_result` frames by matching the most recent trace
  entry for that tool name with no `summary` yet set — safe because the backend loop
  (`AssistantAgentService.runLoop`) executes tool calls sequentially, never concurrently, so arrival order
  is call-then-result, never interleaved across tools.
- `entitlementDenied` is a local `useState`, not synced back into `AuthContext` — a 403 mid-session drops
  the in-flight placeholder turn and flips the SPA to the same upsell card a Basic tenant sees; recovering
  requires a reload (which re-runs `AuthContext.refreshUser()`), same as any other stale-entitlement read
  elsewhere in the shell.
- No conversation-history endpoint exists or was added; history is the existing in-session `messages`
  array only, exactly as scoped.
- Verification: no live backend (Postgres + LLM provider + an authenticated Pro-tier session) was
  available in this session, so `AssistantController`/`AssistantAgentService` were not exercised live -
  `mvn test`'s existing 2.1 coverage is unaffected by this chunk (no backend files touched). The SPA was
  instead verified against the *real* `AiAssistantPage.tsx`/`apiClient.ts` code running in a browser,
  with the backend substituted by a temporary Service Worker mocking `/api/v1/auth/me`, the entitlement
  endpoint, and `/chat/stream` (real SSE-framed bytes matching the format above). Confirmed: live
  tool_call/tool_result trace → final answer + citations render (with working copy buttons); the
  `aiAvailable:false` and `insufficient:true` degraded states render distinctly; the Basic-tier upsell
  card; and the mid-session 403 fallback (Pro tier client-side, stream denied server-side) drops cleanly
  to the same upsell card with no orphaned bubble. `tsc --noEmit` is clean. The Service Worker mock was a
  test harness only and is not part of this change.
