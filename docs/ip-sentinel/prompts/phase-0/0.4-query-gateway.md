# 0.4 — Query gateway (audited PromQL/LogQL proxy)

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

**Goal:** the single, tenant-scoped, audited path the UI and agents use to read metrics/logs. The
browser never talks to Prometheus/Loki directly.

**Deliverables**
- REST endpoints proxying **PromQL** (Prometheus/Thanos) and **LogQL** (Loki).
- Inject the caller's `tenant_id` label into every query; **reject/deny cross-tenant** queries.
- **Per-tenant endpoint resolution:** look up `tenant_datasource` for the caller's tenant; if present +
  enabled, route to that tenant's Prometheus/Loki URL (with its protected credentials via
  `CredentialProtector`); otherwise **fall back to the central endpoint** in `application.yml`. This
  supports central (one endpoint, label-based), per-tenant, and hybrid topologies with the same code.
- Audit each query (who, tenant, resolved endpoint, query, latency) — feeds the governance store (0.7).
- Sensible timeouts, result caps, and error shaping.

**Acceptance**
- A query without a valid tenant scope is rejected; a cross-tenant label injection attempt is blocked (test).
- A tenant **with** a `tenant_datasource` row is queried against **its own** endpoint; a tenant **without**
  one falls back to the **central** endpoint (test both paths).
- Metric + log queries return expected results against a local Prometheus/Loki (Testcontainers/fixtures).
- Every call produces an audit record including the resolved endpoint.
