# 0.4 — Query gateway (audited PromQL/LogQL proxy)

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

**Goal:** the single, tenant-scoped, audited path the UI and agents use to read metrics/logs. The
browser never talks to Prometheus/Loki directly.

**Deliverables**
- REST endpoints proxying **PromQL** (Prometheus/Thanos) and **LogQL** (Loki).
- Inject the caller's `tenant_id` label into every query; **reject/deny cross-tenant** queries.
- **Per-tenant endpoint resolution (multi-source):** gather **all enabled `tenant_datasource` rows of
  the needed kind** (`prometheus`/`thanos` or `loki`) for the caller's tenant; **fan out** the query to
  each source and **merge** results (dedupe by series/stream; tag each with a `source` label). If the
  tenant has **no** enabled source of that kind, **fall back to the central endpoint** in `application.yml`.
  Per-source credentials via `CredentialProtector`. Same code path serves central, per-tenant, and hybrid.
- **Data-source admin API (staff-only):** CRUD for `tenant_datasource` + a **test-connection** endpoint
  (validate URL/auth/reachability before save). Used by the Admin UI (0.8).
- Audit each query (who, tenant, resolved source(s), query, latency) — feeds the governance store (0.7).
- Sensible timeouts, result caps, per-source failure isolation (one bad source ≠ whole query fails), error shaping.

**Acceptance**
- A query without a valid tenant scope is rejected; a cross-tenant label injection attempt is blocked (test).
- A tenant with **multiple** enabled sources is queried against **all** of them and results merged; a tenant
  with **none** falls back to the **central** endpoint (test both paths).
- One unreachable source degrades gracefully (partial results + flag), rather than failing the whole query.
- Test-connection reports reachable/unreachable and does **not** persist on failure.
- Every call produces an audit record including the resolved source(s).
