# 0.12 — Config-driven dashboard engine

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

## Context
`0.10` builds a reusable chart component + 2 pilot dashboards. This chunk makes dashboards cover
**every** monitor type — and **future monitoring** — without hand-coding each one. Dashboards become
**definitions (config/JSON)** rendered by an engine, so a new monitor needs only a new definition.
This is what fully retires Grafana.

## Scope
**In:** dashboard definition schema, a registry, the renderer, a Grafana-JSON importer, seed definitions
for the main monitor categories, and a dashboard picker in the SPA.
**Out:** the chart primitives (`0.10`), the Fleet Overview (`0.9`).

## Dependencies
- `0.10` (chart/stat/table components), `0.4` (query gateway), `0.8` (SPA shell).

## Deliverables

### 1. Dashboard definition format (JSON)
- `{ id, title, category, variables:[tenant,timeRange], panels:[
    { title, type: timeseries|stat|table|logs, query (PromQL/LogQL), unit, thresholds, gridPos } ] }`
- Variables (tenant, time-range) are substituted into queries at render time.

### 2. Storage & registry
- **Bundled** definitions shipped with the app (resources) **+** optional **per-tenant custom** overrides
  in the DB (a `dashboards` table: id, tenant_id NULL=global, definition_json, updated_at).
- A registry that lists available dashboards for a tenant (global + that tenant's custom).

### 3. Renderer
- Reads a definition and composes the `0.10` components; **all queries via the `0.4` gateway** (so
  tenant scoping, audit, and **multi-data-source fan-out** are inherited automatically).
- Handles missing series / bad panel gracefully (one bad panel ≠ broken dashboard).

### 4. Grafana importer
- Convert existing `grafana-dashboards/*.json` (panels + PromQL targets) into the definition format
  (best-effort mapping) to **seed the catalog** — reuse of prior work, not a rewrite.

### 5. Seed definitions (main monitor categories)
- Provide definitions (or imported ones) for IBM i (subsystems, job queues, QSYSOPR, IFS, system
  matrix, SQL-threshold), Windows (CPU/mem/disk/processes, services), SSL/URL/uptime.

### 6. SPA
- **Dashboard picker** (by category/monitor), tenant-scoped; renders any definition; responsive; brand.

## Constraints / gotchas
- **No per-dashboard code** — a new monitor's dashboard is a new definition only (document this).
- Queries always through `0.4`; never direct to Prometheus/Loki.
- Custom per-tenant dashboards must be tenant-isolated.

## Testing
- A dashboard renders **purely from a JSON definition** (no code) via the gateway.
- Importing a `grafana-dashboards/*.json` yields a working SPA dashboard.
- Adding a new definition makes a new dashboard appear with **zero code change** (test).
- With **multiple data sources**, panels show merged results; one bad source/panel degrades gracefully.
- A tenant cannot see another tenant's custom dashboard.

## Acceptance
- [ ] Dashboards are data-driven from definitions; new monitor types need only a definition.
- [ ] Existing Grafana dashboards import and render at parity.
- [ ] Picker lists global + per-tenant dashboards; tenant-scoped; responsive.
- [ ] Works with multiple data sources and with the LLM disabled.
