# 0.9 — Fleet Overview — capacity headroom  ⭐

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

## Context
The **top-priority** screen (fleet-view-first). One pane showing every tenant's health, colored by
**capacity headroom**. Fully deterministic — **no LLM**. This is half the MVP.

## Scope
**In:** headroom scoring service, `/api/fleet` endpoint, the SPA Fleet Overview grid + drill-down link.
**Out:** dashboards (0.10), incidents (Phase 1), forecasting escalation (added later in 3.2).

## Dependencies
- 0.4 query gateway (all metric reads go through it), 0.8 SPA shell, 0.3 tenant scoping.

## Deliverables

### 1. Capacity inputs (per tenant, via the gateway)
Query the four inputs the monitors already expose (confirm exact metric names from the monitors'
`*Metrics*` classes):
- **IBM i ASP/disk %** — from `ibmssystemmatrix`
- **Windows disk %** — from `windowsmonitoring`
- **CPU %** — IBM i (`ibmssystemmatrix`) + Windows (`windowsmonitoring`)
- **Memory / job-queue depth** — Windows memory (`windowsmonitoring`) + IBM i job-queue depth (`ibmjobquecountmonitoring`)

Normalize each to a 0–100 **pressure** value (higher = worse). Handle **missing/stale** series
explicitly (mark "unknown", don't silently score 0).

### 2. Headroom score (weighted blend + hard override)
- **Weighted blend** with configurable weights (defaults, ASP highest): `asp 0.40, disk 0.25,
  cpu 0.20, mem/jobq 0.15`. Weights in `application.yml`.
- **Hard critical override:** per-input critical thresholds (defaults: ASP ≥ 95%, disk ≥ 95%,
  sustained CPU ≥ 95%, job-queue beyond configured cap). **Any** input critical ⇒ tenant = **critical**,
  regardless of the blend (a full disk can't be averaged away).
- Map final score → band: green / amber / red (band cutoffs configurable).

### 3. API
`GET /api/fleet` → `[{ tenantId, name, band, score, worstInput, inputs: [{key, value, band, stale}] }]`
Tenant-scoped (staff see their tenants; a customer sees only theirs). Audited.

### 4. SPA Fleet Overview
- Grid of tenant cards/rows, colored by band; show the worst input + score; **encode severity in
  form** (stripe/badge), not color alone.
- Filter/sort by client, platform, severity. Click → tenant dashboards (0.10).
- Responsive; brand palette; "unknown/stale" rendered distinctly.

## Constraints / gotchas
- Deterministic only — **must run with the LLM disabled**.
- Never read Prometheus directly from the browser — always via 0.4.
- Weighted blends can mask a single critical input — that's exactly what the hard override prevents; test it.

## Testing
- Fixture metrics → assert blended score + band match expected.
- **Override test:** one input critical, others healthy ⇒ tenant red.
- Stale/missing series ⇒ input marked unknown, not scored as healthy.
- Isolation: a customer request returns only their tenant.

## Acceptance
- [ ] Grid shows all in-scope tenants with correct headroom band from live metrics (via 0.4).
- [ ] A single critical resource turns the tenant critical despite healthy others.
- [ ] Works with the LLM disabled.
- [ ] Stale inputs are visibly "unknown", not green.
