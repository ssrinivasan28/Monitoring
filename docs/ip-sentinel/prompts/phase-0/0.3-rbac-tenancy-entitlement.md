# 0.3 — RBAC, tenant isolation & Basic/Pro entitlement

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

**Goal:** two orthogonal access dimensions — **role** (what you can do) and **entitlement/tier**
(what's unlocked) — on top of **strict tenant isolation**.

**Deliverables**
- RBAC roles (e.g. staff-admin, staff-operator, customer-admin, customer-viewer).
- **Per-tenant isolation enforced centrally** — every data access is tenant-scoped; a filter/interceptor
  denies cross-tenant access by default (defense in depth, not per-query opt-in).
- **Entitlement service:** tenant tier (Basic/Pro); a gate the API + UI check (Pro unlocks the Assistant).
- Staff may span multiple tenants; customers are pinned to their own.

**Acceptance**
- A customer-admin cannot read another tenant's data via any endpoint (add a test).
- A Basic-tenant user is denied Assistant endpoints (403 + clear message); a Pro-tenant user is allowed.
- Role checks and tenant scoping are enforced server-side, not just hidden in the UI.
