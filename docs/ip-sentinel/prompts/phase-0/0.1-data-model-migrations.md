# 0.1 — Data model & migrations

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

## Context
This is the first platform chunk. It creates the PostgreSQL 18 schema, migration tooling, and JPA
entities that every later chunk builds on. Get the tenancy, audit-immutability, and vector columns
right here — they are painful to retrofit. See
[enterprise-architecture §8](../../../architecture/enterprise-architecture.md) for the data architecture.

## Scope
**In:** schema, Flyway migrations, `pgvector` enablement, JPA entities/repositories, seed/reference data,
integration test harness.
**Out:** business logic, API endpoints, UI, agents (later chunks). No data collection.

## Prerequisites
- New Spring Boot module `aiops-platform/` exists (created in Sprint 0). If not, scaffold it: Java 17,
  Spring Boot (web, data-jpa, validation), Flyway, PostgreSQL driver, Testcontainers.
- A PostgreSQL 18 instance (local or Testcontainers) with permission to `CREATE EXTENSION`.

## Deliverables

### 1. Flyway setup
- Configure Flyway; migrations under `src/main/resources/db/migration`, named `V1__init.sql`,
  `V2__...`. Flyway runs on startup.
- `V1__init.sql` first statement: `CREATE EXTENSION IF NOT EXISTS vector;`

### 2. Schema (tables, key columns, types)
Every tenant-scoped table has `tenant_id UUID NOT NULL` + an index; timestamps are `timestamptz`.
Use UUID PKs (`gen_random_uuid()`).

- **tenants**(id, name, client_instance_id UNIQUE, status, created_at)
- **users**(id, email, display_name, source ENUM[azure_ad|local|federated], mfa_enabled bool, status, created_at)
- **roles**(id, key) + **user_tenant_roles**(user_id, tenant_id, role_id) — a user's role *per tenant*
- **entitlements**(tenant_id PK, tier ENUM[basic|pro], updated_at) — drives Pro gating
- **monitors**(id, tenant_id, name, kind, port, last_seen_at)
- **alerts**(id, tenant_id, monitor_id, metric, value, threshold, fired_at, cleared_at)
- **incidents**(id, tenant_id, severity, status ENUM[open|ack|assigned|resolved], title,
  root_cause_json JSONB NULL, opened_at, resolved_at, assignee_user_id NULL)
- **incident_signals**(id, incident_id, tenant_id, monitor_id, alert_id, platform ENUM[ibmi|windows], detail_json)
- **correlations**(id, incident_id, rule, window_start, window_end)
- **incident_timeline**(id, incident_id, tenant_id, at, actor, event_type, note) — append-only
- **agent_runs**(id, tenant_id, agent, prompt_redacted, output_json, model, tokens_in, tokens_out, cost,
  created_at) — **append-only (audit)**
- **tool_calls**(id, agent_run_id, tenant_id, tool, args_redacted_json, result_summary, created_at) — **append-only**
- **feedback**(id, tenant_id, subject_type, subject_id, verdict, note, user_id, created_at)
- **kb_docs**(id, tenant_id, source, title, created_at)
- **kb_chunks**(id, kb_doc_id, tenant_id, chunk_text, embedding vector(1536)) — dimension = a config
  constant matching the embedding model; add an **ivfflat**/**hnsw** index on `embedding`
- **forecasts**(id, tenant_id, series, projected_at, projected_value, driver, created_at)
- **threshold_recommendations**(id, tenant_id, series, current, recommended, rationale, status, created_at)
- **cost_ledger**(id, tenant_id, agent_run_id, tokens, cost, created_at)
- **model_config**(id, tenant_id NULL, provider, endpoint, model, active bool)
- **integration_config**(id, tenant_id, kind ENUM[teams|servicenow|jira|pagerduty|opsgenie|siem|email], config_json, enabled)
- **tenant_datasource**(id, tenant_id UNIQUE, prometheus_url, loki_url NULL,
  auth_type ENUM[none|basic|token|mtls] default none, credentials_ref NULL (DPAPI/Key Vault), enabled) —
  optional per-tenant metrics/logs endpoint; **absent ⇒ use the central endpoint from `application.yml`**.
  Enables central, per-tenant, and hybrid topologies. Resolved by the query gateway (0.4).
- **reports**(id, tenant_id, cadence ENUM[daily|weekly|monthly], period_start, period_end, format, storage_ref, created_at)

Indexes: `(tenant_id)` on all tenant tables; `(tenant_id, opened_at)` on incidents; `(tenant_id, fired_at)`
on alerts; vector index on `kb_chunks.embedding`.

### 3. Audit immutability (SOC 2)
- `agent_runs`, `tool_calls`, `incident_timeline` are append-only. Enforce with a Postgres trigger
  that raises on `UPDATE`/`DELETE`, **and** don't expose update/delete in their repositories.

### 4. JPA entities & repositories
- Map each table to an `@Entity`; `@Enumerated(STRING)` for enums; JSONB via a converter or
  `hypersistence-utils` (or `columnDefinition="jsonb"`).
- `embedding` mapped as a `float[]`/vector type (use a pgvector Hibernate type or native queries).
- Repositories are **tenant-parameterized** (every finder takes `tenantId`); no global finders.

### 5. Retention
- Document the **13-month** horizon for time-bound tables (incidents, alerts, agent_runs, tool_calls,
  cost_ledger). A scheduled purge job can come later; here just record the policy + the columns it keys on.

## Constraints / gotchas
- Do **not** create global (non-tenant) finders — isolation starts at the repository.
- `vector(N)` dimension must match the embedding provider (0.5); keep it a single constant.
- Keep `V1` idempotent-safe (`IF NOT EXISTS`) so Testcontainers reruns are clean.

## Testing
- **Testcontainers** with the `pgvector/pgvector:pg18` image (or Postgres 18 + `CREATE EXTENSION`).
- Migration test: Flyway applies `V1..Vn` cleanly from empty.
- Round-trip: insert an `incident` + `incident_signals`; read back.
- Vector: insert two `kb_chunks`, run a `<->` similarity query, assert ordering.
- Immutability: `UPDATE agent_runs ...` throws (trigger) — assert.

## Acceptance
- [ ] App boots; Flyway applies all migrations on Postgres 18 with `pgvector` enabled.
- [ ] Incident + signals round-trip; vector similarity query returns ordered rows.
- [ ] `UPDATE`/`DELETE` on `agent_runs`/`tool_calls`/`incident_timeline` is rejected.
- [ ] Every tenant table has `tenant_id` + index; no global-scope repository finder exists.
- [ ] No change to the 21 monitors (`git diff` = new module only).
