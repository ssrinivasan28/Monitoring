# 4.2 — Platform self-monitoring & observability

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

## Context
The AIOps platform must be monitored like any other system — ideally dogfooded by the existing suite.

## Deliverables
- **Health probes:** liveness / readiness / startup endpoints.
- **Platform metrics** (Prometheus): API latency, agent latency, LLM error rate, integration failures,
  queue depth, DB pool, **cost burn**, per-tenant request volume.
- **Self-alerting:** alert on the platform itself (reuse the existing 21-monitor suite where possible).
- **Structured logs** to Loki; request tracing/correlation ids.
- An "IP Sentinel health" dashboard in the SPA (staff-only).

## Acceptance
- [ ] Probes report accurate health; readiness gates traffic on startup.
- [ ] Platform metrics are scraped and visible; a synthetic failure fires a self-alert.
- [ ] Every request is traceable via a correlation id in logs.
