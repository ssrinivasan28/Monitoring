# 4.3 — Secrets management & rotation

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

## Context
DPAPI works for on-prem, but enterprise/SOC 2 wants a managed secret store with rotation.

## Deliverables
- A **secret provider** abstraction behind `CredentialProtector`: DPAPI (existing) **+ Azure Key Vault**
  (and/or HashiCorp Vault).
- **Rotation without downtime** (cached with TTL + refresh); no long-lived secrets in files.
- A migration path **DPAPI → Key Vault** for existing deployments.
- Startup fails fast (clear error) if a required secret is unresolved.

## Acceptance
- [ ] Secrets resolve from Key Vault/Vault when configured; DPAPI still works on-prem.
- [ ] Rotating a secret takes effect without redeploy (test with TTL refresh).
- [ ] No plaintext secret is written to disk or logs (scan test).
