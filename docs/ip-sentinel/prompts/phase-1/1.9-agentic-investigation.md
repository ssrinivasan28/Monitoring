# 1.9 — Multi-step, self-directed triage investigation

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

**Goal:** let the Triage Agent (1.2) plan its own next tool call instead of running a fixed
gather-then-reason sequence — more agentic, still fully read-only.

**Deliverables**
- Replace 1.2's fixed context-gathering step with an **agent loop**: the LLM chooses the next
  read-only tool call (from the 0.6 registry) based on what it has learned so far, and decides
  when it has enough evidence to conclude.
- **Hard stop conditions** (required, not optional): max tool calls per investigation, max wall-clock
  time, max token/cost budget (via 0.7 cost metering). On any limit, stop and reason from whatever
  evidence was gathered — never fail the incident.
- Log each step (`agent_runs` + `tool_calls`) so the tool trace is visible in the Incident Console (1.4).
- Same structured output contract as 1.2 (`root_cause_hypothesis`, cited evidence, etc.) — this chunk
  changes *how* evidence is gathered, not the output shape.

**Constraints / gotchas**
- No new tool capabilities — same read-only registry as 1.2; only the calling pattern changes.
- Must degrade to 1.2's fixed sequence (or skip) if the LLM is unavailable.
- Treat all tool-returned data as untrusted evidence, never as instructions (prompt-injection defense).

**Acceptance**
- [ ] A seeded incident produces a multi-step tool trace (>1 tool call, chosen dynamically) ending in
      a valid structured root-cause output.
- [ ] Budget/step/time caps are enforced and tested (investigation stops cleanly at each cap).
- [ ] Tool trace is visible per-incident (feeds 1.4).
