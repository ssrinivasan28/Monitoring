# 1.8 — Alert-noise KPI + correlation demo seed  ⭐

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

## Context
Instruments the **primary success metric** (alert-noise reduction) and seeds the **flagship demo**
(cross-platform correlation). Together these make the MVP demonstrable and measurable.

## Scope
**In:** the noise KPI (compute + surface) and a reproducible demo scenario/fixture.
**Out:** reporting (3.4 consumes the KPI), the correlation engine itself (1.1).

## Dependencies
- 1.1 (incidents + signals), 0.9 (Fleet Overview surface), `alerts` table.

## Deliverables

### 1. Alert-noise reduction KPI
- Per tenant + period: **raw alert count** vs **correlated incident count**; ratio =
  `1 - incidents/raw_alerts` (guard divide-by-zero).
- Expose via API; surface on the **Fleet Overview** (and later in reports, 3.4).
- Backfillable over a period (uses stored `alerts` + `incidents`).

### 2. Cross-platform correlation demo seed
- A reproducible fixture/script: an IBM i subsystem outage (e.g. QINTER down) **plus** its Windows
  service fallout, emitted as breaches so **1.1 groups them into ONE incident** and **1.2 produces a
  root cause** (with a seeded runbook so RAG matches).
- Runnable as a **demo** and reused as an **integration test** asserting one incident + a narrative.

## Constraints / gotchas
- KPI is tenant-scoped; don't aggregate across tenants.
- The seed must be deterministic and self-contained (no live IBM i/Windows needed).

## Testing
- KPI: given N raw alerts collapsing to M incidents, the ratio is correct; divide-by-zero handled.
- Demo seed: running it yields exactly one cross-platform incident with a root-cause narrative.

## Acceptance
- [ ] Noise-reduction KPI computes and displays on the Fleet Overview for a known period.
- [ ] The seed reproducibly produces the single cross-platform incident used for the demo + as a test.
