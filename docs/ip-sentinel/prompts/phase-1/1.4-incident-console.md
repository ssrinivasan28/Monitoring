# 1.4 — Incident Console (SPA)  ⭐

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

## Context
Where ranked incidents are read and acted on — the human-facing payoff of correlation + triage.
Must remain fully usable when the AI narrative is absent.

## Scope
**In:** incident list + detail views, severity affordances, push-to-channel action wiring.
**Out:** the correlation/triage logic (1.1/1.2), lifecycle transitions server side (1.5), integrations (1.6/1.7).

## Dependencies
- 1.3 (incident API), 0.8 (SPA shell). Push actions call 1.6 (Teams) / 1.7 (ITSM) once available.

## Deliverables

### 1. Incident list
- Ranked (severity, then recency); columns: severity, title, tenant (staff view), platform(s), status,
  age, signal count.
- Filters: tenant, platform, status, severity. Virtualized if long. Severity encoded as a **stripe/pill**
  (form, not color alone) for accessibility.

### 2. Incident detail
Sections: correlated **signals**; **AI root cause + evidence/queries** (from `root_cause_json`);
matched **runbook**; **similar past incidents**; **timeline**; **suggested checks**.
- **Graceful degradation:** if `root_cause_json` is null (LLM off), hide the AI sections and still show
  signals + timeline + runbook — no broken UI.

### 3. Actions
- "Push to Teams" (1.6) and "Create/enrich ticket" (1.7) buttons — wired, tier/role-gated, with
  success/failure toasts.

## Constraints / gotchas
- Tenant/role scoped via the API; a customer sees only their incidents.
- Responsive; brand palette; keyboard navigable; visible focus.

## Testing
- Renders ranked incidents from 1.3; filters work.
- Detail with a full AI narrative renders all sections; detail **without** a narrative still renders
  signals + timeline (no empty/broken state).
- A customer user cannot open another tenant's incident (guarded).

## Acceptance
- [x] Ranked list + detail render from the API.
- [x] Console fully functions with no AI narrative present.
- [x] Responsive + tenant/role scoped; push actions wired.
