# 3.6 — Proactive, self-triggered investigation

*Prepend [`00-shared-preamble.md`](../00-shared-preamble.md).*

**Goal:** let Anomaly (3.1) and Forecasting (3.2) agents self-trigger a deeper, Triage-style
investigation (1.9) when something crosses a risk threshold — surfacing a ready-made Insight
*before* any monitor breach fires, not just a raw number.

**Deliverables**
- Define a **risk-trigger condition** per signal type (e.g. forecast crosses N days-to-full,
  anomaly score exceeds a tenant-tunable bar). On trigger, kick off the 1.9 investigation loop
  scoped to that signal instead of a breached incident.
- Result is persisted as an **Insight** (not an `incident` — no monitor actually breached) with the
  same evidence-cited structured output as triage, surfaced in Insights (3.5).
- Rate-limit self-triggering per tenant/signal (e.g. once per cooldown window) to avoid
  investigation spam from a noisy trend.

**Constraints / gotchas**
- Read-only, same tool registry and cost/step budgets as 1.9 — no new capabilities.
- Must not create a duplicate `incidents` row; Insights and incidents are distinct tables.
- Degrades cleanly with the LLM off: the raw anomaly/forecast still surfaces, just without the
  investigative narrative.

**Acceptance**
- [ ] A seeded forecast crossing its risk threshold produces an Insight with a cited investigation,
      not a bare number.
- [ ] Cooldown/rate-limit prevents repeat self-triggering within the window.
- [ ] LLM-off ⇒ Insight still appears (from 3.1/3.2), no investigation narrative, no exception.
